# Windows 后台回放（实验）

这个功能只在 Windows 上可用。它是可选的。不勾选时，KeymouseGo 仍使用原来的全局鼠标和键盘，旧脚本的行为不变。

后台模式做三件事：

1. 你从列表里选定一个顶层窗口并绑定。
2. 录制时只留下落在这个窗口客户区内的动作，坐标是相对命中控件的客户区坐标，并记下控件类名和控件 ID。
3. 回放时只对那个控件调用 `PostMessage`。不移动系统光标，不调用 `SetForegroundWindow`，不发送 `WM_ACTIVATE`，不使用 `AttachThreadInput`，也不修改系统剪贴板。

默认停止热键仍是 `F9`。按下后，尚未发出的窗口消息不再发送。

## 不能承诺的范围

前台全局模式是原有行为。若它能驱动某个程序，不表示后台模式也能。

后台消息进的是窗口过程，不是系统输入流。下面这些情况会直接停止，并且不会改回全局输入：

- 找不到窗口，窗口标题或类名已经变了，或同名窗口不止一个
- 窗口最小化
- 子控件找不到，或类名加控件 ID 对应到多个控件。录制时这种点击会被跳过；若脚本里已经写了，回放会停止
- 录制时的 DPI 和当前 DPI 不一样，或只有一边能读到 DPI
- 动作不在支持列表里，或鼠标坐标仍是屏幕百分比
- 普通脚本在后台模式下运行，或后台脚本没有显式打开后台模式

支持的动作：鼠标左键、右键、中键的按下和抬起，鼠标移动，滚轮，普通按键的按下和抬起，以及脚本里的 `input` 文本。文本按 UTF-16 编码后逐字发送 `WM_CHAR`。录制到的按键只有钩子给出的 ASCII 字符会附带 `WM_CHAR`。中文输入法的组合过程不会被记成文字。

侧键不支持。点击标题栏这类非客户区不会写入脚本。

同一个脚本里不要混用普通事件和后台事件。遇到普通事件会停止。

游戏、DirectInput、Raw Input 通常不从这些窗口消息读点击和按键。MIR4 属于这一类。即使前台全局录放对它有效，后台模式也很可能没有任何效果。这不是缺陷，功能不会因此退回全局输入。本仓库的自动化测试使用假窗口接口，在 Linux 上运行，没有在 Windows 上执行，也没有在 MIR4 上执行。

窗口被别的普通窗口盖住时，消息仍发给已绑定的 HWND，不按屏幕最前面的窗口重新命中。这个行为没有在真实 Windows 上验证。最小化窗口不会被还原。

进程仍使用原来的 `SetProcessDPIAware()`，没有改成每监视器 DPI。请在同一缩放、同一块屏幕上录制和回放。缩放变了就会停止。

目标进程的完整性级别如果高于本程序，窗口消息可能失败。失败后脚本停止。本功能不会提升自身权限，也不会注入其他进程。

已有的全局录制钩子还在，用来录制和响应热键。后台回放不会额外安装钩子。

## 界面

1. 打开程序，勾选「后台回放（实验，不保证游戏可用）」。
2. 点「刷新窗口」，在列表里选中目标，再点「绑定所选窗口」。状态行会显示「当前：后台模式，已绑定 …」。
3. 点「录制」，只在目标窗口里操作，再点「结束」。结束按钮在 KeymouseGo 自己的窗口上，后台录制不会把这次点击写进脚本，因此不会像普通模式那样删掉最后两个动作。
4. 点「启动」。运行前必须仍然勾着后台回放。绑定优先于脚本里保存的标题；没有绑定时使用脚本里的标题和类名。
5. 要中途停止，按当前的终止热键（默认 `F9`）。

不勾选时，状态行是「当前：普通模式（全局鼠标键盘）」。这时运行旧脚本仍走全局输入。运行后台脚本会停止并提示需要显式开启后台回放。

## 命令行

在仓库根目录、Windows 上：

```bat
py -3.10 KeymouseGo.py scripts\0101_1200.json5 --background --title "无标题 - 记事本" --class-name Notepad
```

多次执行仍使用原来的参数：

```bat
py -3.10 KeymouseGo.py scripts\0101_1200.json5 -rt 3 --background --title "无标题 - 记事本" --class-name Notepad
```

不带 `--background` 的旧脚本命令保持原样：

```bat
py -3.10 KeymouseGo.py scripts\0314_1452.txt -rt 3
```

`--title` 必须与窗口标题完全一致。有多个相同标题和类名时会停止。命令行里的 `F9` 仍会结束运行。

脚本头部示例：

```json5
{
  replay: "background",
  target: {title: "无标题 - 记事本", class_name: "Notepad"},
  scripts: [
    {
      type: "event",
      event_type: "EM",
      delay: 0,
      action_type: "mouse left down",
      action: [30, 50],
      replay: "background",
      coord: "client",
      dpi: 96,
      child: {level: "child", class_name: "Edit", ctrl_id: 15}
    },
    {
      type: "event",
      event_type: "EX",
      delay: 50,
      action_type: "input",
      action: "你好",
      replay: "background",
      dpi: 96,
      child: {level: "child", class_name: "Edit", ctrl_id: 15}
    }
  ]
}
```

`input` 不会写入系统剪贴板。

## 在 Windows 上从源码运行

需要 64 位 Python 3.10。下面的命令与仓库 `.github/workflows/release.yml` 里的 Windows 任务一致，工作目录是仓库根目录。

```bat
py -3.10 -m pip install -r requirements-windows.txt
py -3.10 -m unittest discover -s tests -t . -v
py -3.10 KeymouseGo.py
```

`requirements-windows.txt` 包含 `pywin32`、`pyWinhook`、`PySide6`、`json5`。这些包面向 Windows。当前这次修改的自动化测试只依赖标准库、`json5` 和 `loguru`，用假的窗口接口，不导入 `pywin32`。

## 在 Windows 上打包

发布流程是手动触发的 `workflow_dispatch`，不会在普通 push 时自动打包，这里也没有触发它。在 Windows 本机打包：

```bat
py -3.10 -m pip install -r requirements-windows.txt
py -3.10 -m pip install pyinstaller
py -3.10 -m PyInstaller -Fw --icon=Mondrian.ico --add-data "./assets;assets" KeymouseGo.py
```

产物在 `dist\KeymouseGo.exe`。工作流里随后把它复制为 `artifact\KeymouseGo_v5_2_1-win.exe`。这次没有生成该 exe。Linux 环境不能用来做出可用的 Windows 可执行文件。

## 建议在 Windows 上亲自验证

1. 记事本：绑定「无标题 - 记事本」，在编辑区点击并输入英文，用另一个窗口盖住记事本后启动后台脚本。看文字是否进入记事本，系统光标是否不动，当前前台窗口是否仍是盖住它的那个窗口。
2. 把记事本最小化后再启动。预期是脚本停止，窗口不会被还原。
3. 打开两个标题相同的记事本且不指定唯一绑定。预期是因为窗口不唯一而停止。
4. 把系统缩放从录制时的值改掉，或把窗口拖到另一块缩放不同的屏幕。预期是 DPI 检查失败并停止。
5. 回放时在前台按住 Shift。前台程序不应收到脚本里的按键；结束后系统修饰键不应卡住。随时可以用 `F9` 停下。
6. 用一个带标准按钮的对话框点击按钮，确认动作落在按钮上，而不是对话框客户区的左上角。
7. MIR4：用前台普通模式确认原有录放仍然可用。再另录一份后台脚本，绑定游戏窗口，让游戏失去前台后只启动后台脚本。预期很可能没有游戏内效果。不要为了让它生效去改注入、驱动或反作弊相关的东西；这个功能没有那条路径。验证结束后，普通模式的旧脚本仍可按原来的方式运行。
